# ИИ-квалификатор для мебельных компаний — демо-бот

Telegram-бот для показа мебельным компаниям: ведёт диалог как менеджер, собирает заявку (текст, голос, фото), делает предварительный расчёт, отдаёт лид менеджеру и в CRM, показывает каталог и «примеряет» мебель на фото комнаты клиента.

Полное ТЗ и архитектура — [tech.md](tech.md), правила разработки — [CLAUDE.md](CLAUDE.md).

## Что нужно

- Токен бота от [@BotFather](https://t.me/BotFather).
- Ключи DeepSeek (диалог) и Polza AI (примерка через Nano Banana, расшифровка голосовых).
- Чат менеджеров для карточек лидов: добавьте туда бота и узнайте id чата (`ADMIN_CHAT_ID`, у групп он отрицательный).
- Для сервера — Docker с compose. Для локальной разработки — Python 3.12, [uv](https://docs.astral.sh/uv/) и GNU make (на Windows: `winget install ezwinports.make`).

## Настройка

```bash
cp .env.example .env
```

Заполните в `.env` как минимум `BOT_TOKEN`, `ADMIN_CHAT_ID`, `DEEPSEEK_API_KEY`, `POLZA_API_KEY`, `POLZA_IMAGE_MODEL`. В `ADMIN_IDS` — tg id тех, кто показывает демо: у них нет дневного лимита примерок. Остальные переменные описаны в `.env.example` и в [tech.md §8](tech.md).

`.env` в git не попадает — на сервере он свой.

## Запуск в Docker (сервер)

```bash
docker compose up -d --build
```

Миграции применяются при старте контейнера, каталог сидится из `assets/catalog/catalog.yaml`. БД и логи лежат в volume `bot-data` и `bot-logs`. Логи: `docker compose logs -f bot`.

Обновление на сервере (бот развёрнут в `/opt/demo-bot`):

```bash
cd /opt/demo-bot && git pull && docker compose up -d --build
```

⚠️ С одним токеном бот может работать только в одном месте: если он запущен на сервере, локальный запуск упадёт с `TelegramConflictError`.

## Шапка бота

Один раз после создания бота (и после изменения текстов шапки в `app/bot/texts.py`):

```bash
make profile
```

Скрипт выставит описание, короткое описание и команды (`/start`, `/delete_me`). Картинку шапки загрузите вручную: @BotFather → `/setdescriptionpic`, файл из `assets/header/`.

## Разработка

```bash
make install    # зависимости (uv sync)
make migrate    # миграции на локальную БД
make run        # запуск бота локально
make test       # pytest
make lint       # pyright + ruff
make fmt        # автоформат
make revision m="msg"   # новая миграция Alembic
```

Внешние API в тестах замоканы — ключи для `make test` не нужны.

## Сценарий демо для клиента

Показ занимает 2–3 минуты. Показывайте со своего аккаунта из `ADMIN_IDS` (без лимита примерок), чат менеджеров держите открытым рядом.

1. **Шапка.** Откройте бота до `/start`: описание «что умеет бот» и картинка — то, что видит клиент первым.
2. **Старт.** `/start` — бот говорит, что это демо, кратко перечисляет, что умеет, упоминает подключение к любому мессенджеру или сайту и предлагает написать запрос. Меню нет: дальше обычная переписка, как с менеджером.
3. **Знакомство.** Напишите запрос, например «Нужна кухня». Бот спросит имя и перейдёт к заказу. Если вместо запроса просто поздороваться, бот предложит представить себя клиентом.
4. **Голос.** Ответьте на вопрос о размерах голосовым: «угловая, три на два метра, МДФ». Бот расшифрует и продолжит.
5. **Фото.** Пришлите фото плана или помещения — бот приложит его к заявке (менеджер увидит его вместе с карточкой).
6. **Каталог.** Когда бот предложит посмотреть примеры — согласитесь (или попросите сами: «покажите примеры»). Полистайте карточки ◀ ▶ и переключите категории.
7. **Примерка — главная фишка.** Под понравившейся карточкой нажмите «🏠 Попробовать у себя» и пришлите фото своей комнаты. Через ~30 с придёт визуализация с этой мебелью в вашем интерьере.
8. **Заявка.** Нажмите «📝 Оставить заявку» под результатом примерки или просто продолжите диалог: город, сроки, бюджет, телефон. Бот поблагодарит и пришлёт предварительную вилку цены.
9. **Что получил менеджер.** Покажите чат менеджеров: карточка лида со всеми полями, телефоном, расчётом и фото. Допишите боту уточнение («кстати, бюджет до 300 тысяч») — менеджеру придёт «✏️ Дополнение к заявке».
10. **Устойчивость.** Напишите ерунду или оскорбление — бот спокойно вернёт к демонстрации.

В конце можно показать `/delete_me` — бот удаляет пользователя и все его заявки (карточки, уже отправленные менеджерам и в CRM, остаются там).

Если что-то пошло не так: `/start` начинает диалог заново, ошибки видны в `docker compose logs bot` (телефоны маскируются, тексты сообщений на INFO не пишутся).
